# Delivery milestones

## Stage 1 — delivered
Architecture, checksummed migration, persistent Windows shell, category/product/variant management, opening stock ledger and catalog tests. Historical verification is retained in TEST_RESULTS.md. The original unsigned installer was blocked by Smart App Control; trusted signing and clean-machine acceptance remain release gates.

## Stage 2 — implemented, hardware acceptance pending
POI template/upload/mapping/preview, row errors and correction export, atomic confirmed imports, explicit stock policies, import history, authorized stock adjustments/history, local owner/billing authentication, permanent Code 128 values, PDF-rendered label previews/PDF export and Windows printer/test-job submission. Tests cover malformed files, duplicates, a late database failure with full rollback, repeat confirmation, stale previews, overdraw prevention, permissions, barcode decoding and restart persistence. Actual printer calibration/scanner checks require the selected hardware. See STAGE_2.md and STAGE_2_TEST_RESULTS.md for evidence and operating limits.

## Stage 3 — implemented in 0.3.0; hardware acceptance pending
POS scan/keyboard workflow; BigDecimal discount/tax policy; split payments; unique checkout keys; transactional stock guard; invoice sequence/snapshots; thermal PDF and print/reprint error handling. Verified simultaneous/repeated checkout, insufficient stock, payment reconciliation, transaction rollback and interrupted confirmation recovery. Basic customer matching/creation is included for billing; full customer history remains Stage 4. See STAGE_3.md and STAGE_3_TEST_RESULTS.md.

## Stage 4 — implemented in 0.4.0
Customer matching/audited corrections, paged purchase history and original receipt details; Indian date/timezone-aware dashboard and sales/payment/stock/customer/valuation/profit reports using committed records; POI/PDF exports. Distinguishes collections, revenue, tax, inventory value and estimated gross profit, with missing-cost coverage. See STAGE_4.md and STAGE_4_TEST_RESULTS.md. Returns/refund reports follow Stage 5's reversal ledger.

## Stage 5 — implemented in 0.5.0
Implemented: extend Stage 2 BCrypt users/permissions with account lifecycle/recovery and finer permissions; administrator reset/recovery of billing-user passwords; partial returns/refunds/cancellation ledger; verified consistent backups, retention, test restore and export utility. An administrator-managed operating-expense ledger (expense category, amount, date, payment method and audit actor) so monthly reports can show net profit/loss after expenses, while retaining the existing gross-profit estimate. The approved billing discount selector supporting either a percentage or a fixed rupee amount, with authorization and calculation validation. WhatsApp receipt sharing preparation saves PDF/PNG and opens a chat for manual attachment/review/send; it does not send automatically or confirm delivery. See STAGE_5.md and STAGE_5_TEST_RESULTS.md. Test repeated/remainder returns, account changes, both discount modes, expense totals, net-profit reconciliation, WhatsApp export handling and restored counts/money totals.

## Stage 6 — software candidate 0.6.0, release acceptance pending
Implemented user-requested Windows Share with PDF/PNG attachment (operator selects target/customer and Send), country-code selection and backend mobile validation at creation/correction/checkout, normalized international contacts with legacy correction warnings, and live backend-priced New Bill line/summary totals. Vertical barcode behavior is retained. Release work includes native helper build, bundled runtime packaging, isolated packaged acceptance, forced interruption recovery, backup compatibility, signature/hash checks and handover documentation. Full acceptance includes trusted signed distribution, clean-machine installation, Windows reboot/physically offline tests, real scanner/58 mm/80 mm/label printer checks and actual WhatsApp target acceptance. Hardware behavior must be demonstrated on the selected devices. Production release is gated on all essential features and acceptance evidence; a catalog-only build is not a completed POS.

Stage 6 does not authorize paid WhatsApp API/cloud messaging. Prior administrator password recovery, INR/% discounts and monthly net profit/loss were delivered in Stage 5 and are covered by regression tests. See STAGE_6.md, STAGE_6_TEST_RESULTS.md and RELEASE.md for current evidence and gates.
